# Day 02 Notes

## Core Concepts

Business Goal
= why the project exists

Functional Requirement
= what the system does

Non-Functional Requirement
= how well the system works

Constraint
= limitation on the solution

User Story
= requirement from the user's perspective

Business Rule
= rule that controls behavior

Acceptance Criterion
= condition used to verify correctness

Out of Scope
= what the current version will not do

---

## Important Rule

Never assume missing details.

Ask clarification questions first.

## MoSCoW

Must Have
= required

Should Have
= important

Could Have
= optional improvement

Won't Have
= not part of the current version

---

## MVP Question

Ask:

Can we launch the product without this feature?

If no:
Must Have

If yes, but important:
Should Have

If it is only an improvement:
Could Have

If it is outside the current release:
Won't Have
